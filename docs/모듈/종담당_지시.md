## 파일 주인
- 내 것: 맡은 종의 `plugin/src/main/java/kr/gave/mob/sp/Gxx.java`(+ `Gxx*.java` 도우미), `tools/gabe/sp/gxx.py`, `data/phrases/Gxx.json`(make_gabe 가 씀), `tools/scenarios/sp_gxx*.json`.
- 그 밖은 모두 읽기 전용. 공용 API 가 없거나 버그면 내 파일 안에서 돌아가게 하고, 필요한 바뀜을 보고의 "요청"에 적는다(어느 파일, 무엇을). 종 기본값(`tools/gen_species.py` 의 TUNE: 체력, 점수, 보상, 띠, 나오는 방식)도 공용이라 바꾸고 싶으면 요청에.
- 다른 작업자 여럿이 같은 트리에서 다른 종을 동시에 만든다. 진짜 트리를 깨진 채로 두지 않는다.

## 일하는 법
- Java: `build/wip/<내 이름>/plugin/src/main/java/...` 에 먼저 쓰고 `python -X utf8 tools/compile_wip.py --name <내 이름>` 으로 따로 컴파일. 통과하면 `--promote` 로 진짜 자리에 옮긴다. **종 하나가 컴파일되고 기본 확인을 넘기면 바로 promote 한다**(작업이 중간에 끊겨도 잃지 않게).
- 팩: `python -X utf8 tools/make_gabe.py --only gxx --preview`(잠금이 있어 여럿이 돌려도 됨). 글귀, 아이콘, 덮개를 바꿨으면 `python -X utf8 tools/make_hud.py && python -X utf8 tools/compile_wip.py --name hud --promote`.
- 게임 안 시험: `python -X utf8 tools/ingame.py --name <내 이름> --scenario tools/scenarios/<대본>.json [--keep-pack] > build/<내 이름>/<기록>.out 2>&1`. 서버를 띄우므로 출력을 파이프로 받지 말 것(파일로). PC 전체에서 한 번에 하나만 돌고 줄을 선다(오래 기다릴 수 있음, 백그라운드로 돌리고 끝을 기다릴 것). 대본 하나는 3분 안쪽, 여러 종을 한 대본에 묶는다. `/gave 소환 <Gxx> <수> <거리> Ripley` 와 시험 훅(보기, 쏘기, 몹보기, 몹정지, 사람상태 등, API.md 12장)을 쓴다. 사진은 직접 본다(png 를 Read). 본 뒤 사진, 영상은 지운다(종마다 작은 증거 한 장까지만 `build/evidence/<내 이름>/`).
- 알려진 환경 문제: 26.3 시험 클라가 서버 팩을 읽은 직후 가끔 0xC0000005(spirv-cross.dll)로 꺼진다. ingame.py 가 다시 띄운다. 그 때문에 무효가 된 실행은 다시 돌린다. 시험 훅 '보기' 는 벽을 무시하고 겨눈다.
- 진행 기록: `build/<내 이름>/progress.md` 에 종마다 한 줄씩(상태, 남은 일) 바로바로 적는다. 작업이 끊기면 다음 사람이 이 글로 이어 간다.

## 종마다 지킬 것
- 도감 항목(생김새, 움직임, 공격, 불쾌 포인트, 알아보는 신호, 대처법)을 따른다. 26.3 바닐라 클라에서 엔진이 잘 못 하는 것은 가장 가까운 튼튼한 방법으로 바꾸고 무엇을 바꿨는지 적는다.
- 공통 규칙: 어딘가에 펄럭이는 엔드 막대기 둘(원형 DNA). 실눈 = 아직 안 봄, 눈 뜸 = 너를 찍음(`mark()`). 3블록 안 사람 얼굴은 키트가 준다. 종 고유 신호 소리 하나와 한국어 자막. 죽은 이유 글귀 `cause_gxx`(짧게, 예: '말소리를 들켰다'). 소환, 분열, 조각으로 생긴 개체는 보상 0(`noReward`). 디스플레이 점수를 아낀다. 체력 막대 달린 거대 단일 몹(보스) 금지.
- 사람 피해는 모두 `hit()`(= `game.players.hurt`)로. 사람에게 건 것(느려짐, 묶임, 붙잡힘, 덮기, 잠복, 머리 부착)은 그 개체가 죽거나 웨이브가 끝나면 반드시 풀린다. 나간 사람, 쓰러진 사람에 대한 null 처리. 매 틱 큰 할당 금지(30명, 200마리 기준).
- 우리 개체(`game.director.cageSpawning()`)일 때는 `spawned()` 에서 사람 쪽 일을 하지 않는다. 사람을 잡는 PLACED 종은 `mark(p)` 로 target 을 세운다. G38, G52, G50 은 noReward 를 켜지 않는다.

## 절대 규칙
- Windows + Git Bash. 역슬래시가 든 파일은 Write 도구로(bash heredoc 은 역슬래시 둘을 하나로 줄임). CRLF 파일에 `sed -i` 금지(Edit 도구나 파이썬 바이트 치환).
- 이 PC 에는 다른 세션의 마크 서버와 시험 클라가 돈다(포트 25565, 25940대, 26000~26199, 8088, 8215, 8250대, 8270 등). 절대 건드리지 않는다. 게이브는 26200+10N, 26201+10N, 팩 8290+N 만 쓴다. 시험 클라는 PC 전체 2대까지(ingame.py 가 지킴), 소리는 늘 꺼짐. 시험 계정은 Ripley, Bishop 만(실제 작품 속 이름. 코드 예시, 글귀에도 지어낸 이름 금지).
- 가운뎃점(U+00B7) 금지(코드, 주석, 문서, 팩 글자 어디에도).
- 연출: 탄, 빛줄기, 실, 사슬, 투사체를 setGlowing 외곽선이나 block_display 상자 하나로 그리지 않는다. 셰이더 모양이나 텍스처 입힌 아이템 모델로.
- UI: 설명 글 벽 금지, 짧은 글귀 하나까지.
- 웹소설 크리쳐의 이름, 고유 생김새를 이름이나 글에 쓰지 않는다(공포 장치만 빌렸다).
- _Gave 얼굴은 팩 텍스처로만(프로필 조회 금지). 실제 플레이어의 채팅을 되풀이하지 않는다(시스템이 지어낸 말은 분홍 글씨 글귀로).
- C: 여유가 적다. 큰 사본을 만들지 않는다.
- 보고는 솔직하게: 확인한 것(명령과 결과)과 확인 못 한 것을 가른다.
