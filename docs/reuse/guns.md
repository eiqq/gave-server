## 1. Data model and item construction

### Kind, Recoil, Spec
- `enum Kind { PISTOL, SMG, SHOTGUN, RIFLE, SNIPER }`. The arrays in `Arms` are indexed by `Kind.ordinal()`, so a player can hold only one gun of each Kind.
- `record Recoil(double climb, int climbMax, double pattern, double phase, double recover, double fov)`
  - Vertical kick at shot n = `1 + climb*min(n-1, climbMax)`.
  - Side kick follows a sine pattern (amplitude `pattern`, offset `phase`).
  - `recover` is the share of the climb that is returned after release.
  - `fov` is the FOV multiplier applied while firing.
- `record Spec(Kind kind, String key, String name, int mag, int reserve, double rps, double spread, double bloom, double bloomMax, double move, double up, double side, int reload, int pellets, double range, int pierce, boolean shells, String vanillaModel, Sound fire, float pitch, int draw, double soundRange, Recoil recoil)`
  - Units: spread, bloom, move, up and side are degrees. reload and draw are ticks (for the shotgun, `reload` is ticks per shell). range and soundRange are blocks. `reserve=-1` means infinite.
  - `key` is the base name for the item model, the sound events (`gun.<key>.*`) and the HUD icons (`gun_s_/gun_l_/gun_m_<key>`, `_nomag`).
  - `name` (Korean) is the `how` string passed to `killZombie`. The kill feed matches either `name` or `key`.
- `static final Map<Kind,Spec> SPECS` (EnumMap, static block). Key values:

| key | mag | res | rps | spread | pellets | range | pierce | reload | draw | soundRange |
|---|---|---|---|---|---|---|---|---|---|---|
| pistol | 15 | -1 | 5 | 1.2 | 1 | 80 | 0 | 28 | 8 | 64 |
| smg | 40 | 240 | 13 | 1.6 | 1 | 70 | 0 | 36 | 9 | 80 |
| shotgun | 8 | 48 | 1.2 | 5.0 | 9 | 25 | 0 | 9/shell | 10 | 80 |
| rifle | 30 | 180 | 10 | 1.0 | 1 | 120 | 0 | 44 | 10 | 96 |
| sniper | 10 | 50 | 1.6 | 0.1 | 1 | 160 | 4 | 52 | 12 | 128 |

### Arms (per-player state, `Map<UUID,Arms> arms`)
- Public fields: `primary`, `mag[]`, `res[]`, `grenades`, `shots`, `kills`.
- Package-private fields: `next[]` (a fractional next-shot tick for each gun), `bloom`, `reloading`, `reloadUntil`, `reloadStart`, `phaseStart`, `reloadEmpty`, `magOut`, `shellPhase`, `cueIdx`, `fireAfterPump`, the cycle state (`cycleKind/At/Step`, `cycleOwed[]`), the input state (`tapUntil`, `confirmedAt`, `probeAt`, `holdNoFire`, `simUntil`), the recoil state (`burst`, `climb`, `drift`, `restYaw/Pitch`, `recYaw/Pitch`, `recStep`, `fovUntil`, `fovMul`, `sentWalk`), and the visual state (`flashAt`, `flashSeed`, `sentStamp[2]`, `sentMag[2]`, `drawAt`, `reloadWt`, `poseEndWt/Kind`, `debug*Until`).
- If you move the code to another package, make these fields public or keep `Arms` in the same package as `Guns`.
- Slots are fixed: 0 is the primary, 1 is the pistol. `onHeld` cancels any slot above 1. `held(p)` maps the current slot to a Spec.

### Gun item: `static ItemStack item(Spec s)`
- Base call: `Props.vanillaLook(Material.STICK, s.vanillaModel(), s.key(), Component.empty())`. This produces a STICK with `item_model = zombierun:<key>` when the key is in the pack's `props.json`, otherwise `minecraft:<vanillaModel>`. The item name is empty, which suppresses the hotbar name popup, and the tooltip is hidden.
- Components added on top:
  - `CONSUMABLE`: consumeSeconds 100000, animation NONE, no particles, sound `minecraft:intentionally_empty`. This is what makes "hold" possible.
  - `USE_EFFECTS`: canSprint true, speedMultiplier 1, interactVibrations false. Without this, holding the trigger slows the player and stops sprinting.
  - `ATTRIBUTE_MODIFIERS`: ENTITY_INTERACTION_RANGE -3 on MAINHAND (key `zombierun:gun_entity_range`).
  - `ATTACK_RANGE`: min = max = 64, hitboxMargin 0.
  - `INTERACT_ANIMATION`: SwingAnimation NONE.
  - The code has no comment explaining the two range components. My inference: they stop clicks from targeting entities (melee hits or interact-entity packets), so every click goes to use-item. Keep them.
- `custom_model_data` is written per tick by `visual()` (section 4). Item definitions are generated by `build_pack.py gun_items()`:
  - `select display_context`: gui shows `minecraft:empty`; firstperson_* shows a composite of the kick-tinted body plus `muzzle_<gun>`; everything else falls back to the plain body plus the muzzle.
  - `condition custom_model_data index 0` switches between `<gun>` and `<gun>_nomag`.
  - `hand_animation_on_swap:false`.

## 2. Firing pipeline

### Input
- `onInteract(PlayerInteractEvent)` at priority HIGH:
  - Always calls `setUseInteractedBlock(DENY)`. Only the main hand and right clicks are handled.
  - A press counts as fresh when `!usingHand(p)` (`isHandRaised && activeItemHand==HAND`). If the server still thinks the item is in use, the event is a repeat press answering a probe, not a new tap.
  - On a fresh press, `g.loot.tryUse(p)` runs first. If it consumed the press, `holdNoFire=true` until release. Otherwise `tapUntil=now+4`, which guarantees one shot for very short clicks.
  - Every accepted press sets `confirmedAt=now` and `probeAt=-1`.
- `triggerHeld(p,a,tk)` decides whether the trigger is held:
  - `simUntil` (test hook) forces it true.
  - It is false when the player is not using the item, is a spectator, has `holdNoFire`, or has a non-CRAFTING inventory open.
  - Every 10 ticks after the last confirmation, the server sends the shooter only a `ClientboundSetEntityDataPacket` with `GlowNet.LIVING_FLAGS & ~1` (bit 0 cleared means "not using"). A client that still holds the button re-sends use-item.
  - While waiting for that answer, firing continues only for `graceTicks = ceil(ping/50)+2`. After `holdGap+2` ticks (`holdGap = max(6, ceil(ping/50)+3)`) the server calls `p.clearActiveItem()`.
  - Reason, from the code comment (same method as the scpsl Firearms code): chat or Esc never sends a release.
  - `LIVING_FLAGS` is obtained by reflection on the Mojang-mapped field `LivingEntity.DATA_LIVING_ENTITY_FLAGS` (GlowNet lines 42-54). Copy only that accessor; the rest of GlowNet is zombie glow.
- Other inputs:
  - Q, `onDrop`: cancelled, then `reload(p)`.
  - F, `onSwap`: cancelled, then `g.grenades.throwFrom(p)`.
  - Left click, `onSwing` with ARM_SWING: `shove()`, which is zombie-specific.

### Tick (`tick()`, called by Game after `zombies.tick()`)
For each player in `g.alive()`:
1. Smooth the movement speed: `speed = speed*0.6 + hyp*0.4`.
2. Decay bloom: `bloom *= 0.82` once more than 2 ticks have passed since the last shot.
3. `recoilTick`.
4. If the held Spec is non-null:
   - `cycleTick` (post-shot pump or bolt sounds).
   - Cancel the reload if the player switched guns, otherwise `reloadTick`.
   - `trigger = triggerHeld || now <= tapUntil`. It is forced false when `!g.running()`, when the player is grabbed, or during the draw time.
   - If the trigger is on, call `pull()`.
5. `visual()`.

### Cadence: `pull()`
- `if (next[k] < now-1) next[k] = now`.
- `while (next[k] <= now && fired < 3) { fire(); next[k] += 20/rps; }`
- Fractional accumulation keeps 13 rps at 13 (resetting to `now` every tick would drop it to 10). Cadence is stored per gun, so swapping guns cannot skip the pump or bolt time.
- Firing an empty mag plays a dry click once, sets `next = now+6` and starts an auto-reload.
- Shotgun during a reload: with at least 1 shell loaded, firing interrupts the reload. If the reload started from empty, the gun pumps first and then fires (`fireAfterPump`).

### `fire()`
- Spread: `spread + bloom + move*min(1, speed/0.22) + (airborne ? move*1.5 : 0)`, multiplied by 0.6 while sneaking.
- `cone(dir, deg)` samples uniformly over a disk (`sqrt(rand)` radius).
- For each pellet: `trace(...)`, plus `g.fx.tracer` for pellets 0-2 only.
- Then `bloom = min(bloomMax, bloom + s.bloom())` and `recoilShot`.
- Fire sound: `Props.soundAround(eye, "gun.<key>.fire", s.fire(), 1, 0.96..1.04, s.pitch(), s.soundRange(), -1)`.
- Sets the muzzle flash stamp. The entity-based muzzle fallback is used only when `!Props.has(key)`.
- Then `whiz()`, then an auto-reload at mag 0, or a pump or bolt cycle for SHOTGUN and SNIPER.

### Recoil and FOV
- `static kick(Player, yaw, pitch)` sends `ClientboundPlayerRotationPacket(yaw, true, pitch, true)`. This is a relative rotation, so it never takes the mouse away from the player. Grenade and respawn shakes reuse it.
- `recoilShot`:
  - `up = s.up*(1+climb*min(n-1, climbMax))*(0.9..1.1)*crouch(0.75)`.
  - Side kick = sine pattern ramped over shots 2-6, plus random.
  - 65% is sent this tick and 35% next tick (`restAt`).
- Release is detected at `now - lastShot > min(lastInterval, 5) + 3`. The gun then returns `climb*recover` pitch and `-drift*0.3` yaw over 6 ticks, with weights `RECOVER = {.3,.25,.18,.13,.09,.05}`.
- FOV kick: for 2 ticks, `fov()` sends a client-only `ClientboundPlayerAbilitiesPacket` with a modified walkingSpeed. The formula is FOV mult = `(moveAttr/walk + 1)/2`, solved for walk. `forget()` restores the real value.

### Reload state machine
- `reload(p)` refuses when `stale()` (tick() has not run for 2 ticks or more), when already reloading, when grabbed, when the mag is full or when there is no reserve.
- Magazine guns:
  - `reloadUntil = now + s.reload()`.
  - A `CUES` list per Kind of `Cue(int at, int act, boolean emptyOnly, float pitch, Sound fallback, String... events)`. `act` is NONE, MAG_OUT (sets `magOut=true`, which swaps to the `_nomag` model) or MAG_IN.
  - A cue plays the first of its events that the pack has (`Props.hasSound`), otherwise its vanilla fallback.
  - Example, pistol: 0 mag_out sound, 5 MAG_OUT, 14 mag_in sound, 18 MAG_IN, 22 slide (empty-only).
  - The code comment says sound times were moved earlier so the loud click in each waveform lands on the visual swap tick.
  - On completion: `take = min(mag-cur, res)`, then `cancelReload()`.
- Shotgun (`shells`):
  - `SHELL_START=7` (reload_start sound), then 9 ticks per shell with the `shell` sound (variant 1) at `reloadUntil-1`.
  - At the end: `startPump` (`SHELL_PUMP=8`, `pump` sound) if the reload started empty, otherwise the `reload_end` sound.
- `cancelReload` records `poseEndWt` so the shader can play the return-from-reload pose.
- Switching guns (`switched`) cancels the reload and sets `drawUntil`. An unfinished pump or bolt cycle is marked `cycleOwed` and replayed during the next draw.

## 3. Hit resolution (the plug-in seam)

`private Location trace(Player p, Location eye, Vector d, Spec s, int pellet, boolean sound)`:
```java
RayTraceResult r = p.getWorld().rayTrace(from, d, left, FluidCollisionMode.NEVER, true /*ignorePassable*/, 0.25 /*raySize*/,
    e -> e != p && !hit.contains(e) && g.isZombieTarget(e));
```
- This uses Bukkit's combined block-plus-entity ray trace. Entities are tested by their real bounding boxes inflated by 0.25 per side, and the nearest hit wins. Passable blocks such as grass are ignored.
- In zombierun the targets are real Players (human zombies) and vanilla `Zombie` mob bots. `g.isZombieTarget(e)` is `running() && zombies.get(e) != null`.
- Entity hit:
  1. `hit.add(z)` and `a.kills++` (this counts hits, not deaths).
  2. `g.fx.shots.bloodHit(at, d, pellet<3)`.
  3. `impact.flesh` sound if `sound`.
  4. `g.killZombie(z, p, s.name())`. **Every hit is a kill: there is no HP or damage model.**
  5. Pierce: `if (pierce-- > 0) { left -= dist; from = at + d*0.05; continue if left > 0.5 }`. The sniper (pierce 4) can hit up to 5 targets. Pierce never passes through blocks.
- Block hit: `g.fx.shots.hit(at, face, material, d, pellet<3)` plus `impactSound` (metal, wood, glass, or stone by default). BARRIER blocks stop bullets but get no decal, because barriers are prop collision blocks.
- Shotgun: 9 independent cones. Only the first 3 pellets get impact sounds (the `sounds<3` counter), full effects and tracers.

**Seam for fake mobs.** Replace the single `rayTrace` call with the code below. The loop body stays the same.
```java
interface HitTargets {
  Hit cast(Vector origin, Vector dir, double maxDist, Set<Object> exclude); // nearest
  boolean damage(Object target, double dmg, Player by, String how, Vector at, Vector dir); // true = died
  List<Object> inRadius(Location c, double r);   // grenades
  Vector center(Object target);                   // grenade LOS, shove
}
record Hit(Object target, Vector pos, double dist) {}
```
In `trace`:
1. `rb = world.rayTraceBlocks(from, d, left, NEVER, true)`.
2. `blockDist = rb==null ? left : rb.hitPos.distance(from)`.
3. `h = targets.cast(from, d, blockDist, hitSet)`.
4. If `h != null`, run the entity branch, replacing `killZombie` with `damage(...)`. Otherwise, if `rb != null`, run the block branch. Otherwise return the end point.

Notes for the fake-mob side:
- Sphere test: `t = (c-o)·d; m2 = |c-o|^2 - t^2; hit if m2 < R^2, at t - sqrt(R^2-m2)`.
- Add about 0.25 to R to match the current forgiveness.
- Brute force is fine. Worst case is about 400 rays/s (30 players with SMGs) against a few hundred spheres.
- Use the `exclude` set for pierce, the same way `hit` works now.

## 4. Visual effects (ShotFx, Fx, the shader)

### Rendering method
- Every effect is an `ItemDisplay` holding a PAPER item with `item_model = zombierun:fx_quad | fx_tracer | fx_flat`.
- Its single `custom_model_data` color carries the bits `[kind 4][seed 8][start tick mod 4000, 12]`. The top 2 bits of the seed are a variant.
- `pack_fx/zrfx.glsl`, hooked into vanilla 26.3 `core/item.vsh` and `item.fsh` by `make_fx.py`, detects the marker texture `fx_marker.png`, where each pixel is `(x*4+1, y*4+1, 197, 254)`. It then draws the shape procedurally with `age = mod(GameTime*24000 - start, 4000)`.
- No particles and no glowing boxes. This follows a user rule.
- Kinds: TRACER=1, FLASH=2, DUST=3, SPARK=4, DECAL=5 (variants HOLE/SCORCH/BLOOD/BILE), FIRE=6, RING=7, SMOKE=8, BILE=9, BLOOD=10, and muzzle kinds 11, 12, 13 inside the gun model.
- `make_fx.py` reads the vanilla shaders from `~/.cache/mc-shader-vanilla/26.3/...`. Its patch anchors must match exactly, otherwise it exits.

### Spawning helpers
- `spawn(at, model, kind, variant, Matrix4f, Billboard, glow, lifeTicks[, visibleByDefault])`. It always spawns with yaw and pitch 0 and orients only through the matrix. Settings: `setPersistent(false)`, transform NONE, brightness 15 when glowing, `viewRange 2.5` (about 160 blocks). Every display goes into a `timed` list and is removed in `tick()` once `g.now() >= life`.
- `grow(d, matrix, ticks)` and `drift(d, loc, ticks)` are scheduled 1 tick later. This is required, because interpolation set in the spawn tick does not play. Teleport duration is capped at 59.

### Public API
- `tracer(shooter, eye, end, main)`:
  - Starts at the first-person muzzle offset (eye + look·1.2 + right·0.36 + up·-0.26), then 1.2 blocks further along the shot.
  - Length is a quarter of the travel distance, clamped 0.8..4.5. Skipped when travel is under 2.
  - Flies in 1-3 ticks. Life is that flight time plus 4 ticks.
- `muzzle(p)`: fallback flash. Uses one quad shown only to the shooter via `showEntity` and another shown to everyone else.
- `hit(at, BlockFace, Material, dir, full)`: hole decal (0.3 blocks, 200 ticks). With `full`, adds dust tinted by material (`dustColor`) and sparks (not for wood). `static int material(Material)` returns MAT_STONE, MAT_METAL, MAT_WOOD or MAT_GLASS.
- `bloodHit(at, dir, full)`: blood mist. With `full`, adds an exit spray and a blood decal on a wall within 3.5 blocks or on the floor within 2.6 blocks.
- `explosion(at)`: flash, 3 fireballs, ground ring, 3 smoke puffs, scorch mark.
- `burst(at)`: bile splash. Reusable as an acid-type mob effect.
- `tick()`, `clear()`, `alive()`.

### Budgets
- Decals are capped per type in FIFO deques: `MAX_HOLES 56`, `MAX_BLOOD 18`, `MAX_BIG 6`. Separate caps stop SMG holes from evicting scorch marks.
- Tracers, dust, sparks and mist have **no cap**. For Gave with 30 players, about 400 shots/s would spawn more than 1500 displays/s. Add a global budget per tick, or drop `full` effects when the count is high.

### Muzzle flash and first-person gun motion (`Guns.visual`)
The held gun's `custom_model_data` is rewritten only when the computed key changes (followed by `setItem(slot)`):
- `flags[0]` = magazine out.
- `colors[0..2]` = third-person muzzle flash: `kindFx<<20 | (seed&~KICK_BIT)<<12 | stamp`.
- `colors[3]` = first-person body gesture: `(0xF0|st>>8&15)<<16 | (sig<<4|st>>4&15)<<8 | (15-level)<<4 | st&15`. `sig` is E for recoil, D for draw, C for reload pose, B for leaving the reload pose. White means no gesture.
- `colors[4..6]` = first-person muzzle flash with `KICK_BIT = 1<<5`.
- seed = `kickLevel<<6 | KICK_BIT | rand32`. `kickLevel`: SMG 0, RIFLE 1, PISTOL 2, others 3.
- The stamp is kept for `FLASH_KEEP=4` ticks.

**Gotcha:** stamps use `world.getGameTime()` (`worldTime()`), not `g.now()`, because the shader reads `GameTime`.

The first-person tints exist only in the firstperson_* item contexts, so a teammate's gun next to your camera does not move in your view.

### `Fx` facade
- It only adds `corpse(Entity, Zed.Type)` (Mannequin) and `rope(Zed, ...)` chains. Both are zombie-specific; skip them.
- In Gave, call `ShotFx` directly. ShotFx needs only `g.world`, `g.now()` and `g.plugin`.

## 5. Sounds

- Everything goes through `Props`:
  - `soundAround(Location, String event, Sound fallback, float vol, float jitter, float fallbackPitch, double range, int variant)` sends to each player within `range`.
  - `soundTo(Player, Location, ...)` sends to one player.
  - `sound(Location|Player, ...)`.
- Mod sound events are `zombierun:<event>`. They are used only if the served pack zip's `assets/zombierun/sounds.json` contains them (`Props.packSounds(byte[] zip)`, called by PackServer). Otherwise the vanilla fallback plays at volume `max(vol, range/16)` and pitch `fallbackPitch*jitter`.
- Pitch contract: the audible pitch of mod sounds comes from `sounds.json`. The Java pitch value is only for the vanilla fallback.
- Events used:
  - `gun.<key>.{fire, draw, dry, mag_out, mag_in}`
  - `gun.pistol.slide`, `gun.{smg,rifle}.charge`, `gun.sniper.{bolt_pull, bolt_release}`
  - `gun.shotgun.{reload_start, shell, reload_end, pump}`
  - `impact.{flesh, metal, wood, stone}` (glass is vanilla only), `bullet.whiz` (no fallback)
  - `grenade.{pin, spoon, bounce, explode, explode_far}`
- Vanilla fallbacks: FIREWORK_ROCKET_BLAST / LARGE_BLAST / GENERIC_EXPLODE for shots, IRON_TRAPDOOR_OPEN/CLOSE, PISTON_EXTEND/CONTRACT, DISPENSER_FAIL, ITEM_ARMOR_EQUIP_IRON, PLAYER_HURT, ANVIL_LAND, WOOD_HIT, STONE_HIT, GLASS_HIT.
- Source files come from `tools/props/build_more.py SOUNDS`: Timeless and Classics Guns 0.3.14.2, Just Enough Guns 0.14.5, TAC GEAR 0.7.1.
  - `attenuation_distance` is set to match the Java ranges.
  - Per `docs/소품출처.md`, the provenance of 65 of 68 sound files is unverified. Re-check before reusing them in a distributed pack.
  - The TaC gun models carry CC BY-NC-SA 4.0 and GPL-3.0, and `CREDITS.txt` is mandatory (`build_pack.py` fails without it).
- `whiz()`: plays to each player other than the shooter whose eye is within 2.5 blocks of the shot segment, with a 3-tick cooldown per listener.

## 7. Zombie-specific coupling and adaptation plan for Gave

### Couplings to cut

| Call | Where | Gave replacement |
|---|---|---|
| `g.isZombieTarget`, `g.killZombie` | `trace` | `HitTargets.cast` and `damage` |
| `g.zombies.entities()`, `stun()` | `shove`, `Grenades.explode`, test 좀비부르기 | `targets.inRadius`, knockback on fake mobs, or drop shove |
| `g.zombies.isGrabbed(p)` | tick, reload, onSwap, shove | `false`, or Gave's downed/stunned check |
| `Zombies.resetBody(p)` | `equip` | Gave attribute reset |
| `g.loot.tryUse(p)` | `onInteract` | central shop interaction (keep the `holdNoFire` behaviour) |
| `g.alive/running/inGame/now/world/plugin/fx/grenades/guns` | throughout | small `Ctx` interface |
| `Fx.corpse/rope`, `Zed`, `GlowNet` | Fx, GlowNet | drop; keep only the `LIVING_FLAGS` accessor |
| `Hud` | reads `SPECS`, `arms.primary`, `held`, `ammo(p) -> {mag, res\|-1, reload 0..1\|-1}`, `reloadPhase(p) -> {left, len}` | keep these signatures |
| Namespace `zombierun` | `Props.NS`, `make_fx.py`, `build_pack.py`, `#include <zombierun:zrfx.glsl>`, the `RANGE_ENTITY` key | rename everywhere at once, or keep it |

Keep the `Guns` constructor's 1-tick `watch()` task and `settle()`. They reset visuals when the game stops calling `tick()`.

### Stat hooks
Add `final Spec[] eff = new Spec[Kind.values().length]` to `Arms`, rebuilt by `Spec withMods(Mods m)`, where `Mods` holds dmgMul, rpsMul, magAdd, reloadMul, spreadMul, pierceAdd, rangeMul, pelletAdd and recoilMul. Then route every `SPECS.get(...)` and `held()` through `eff`: `held`, `switched`, `givePrimary`, `refill*`, `visual` (drawLen), `cycleTick`.

| Stat | Where it hooks |
|---|---|
| Damage | `trace` entity branch: `damage(target, baseDmg*dmgMul*falloff(dist))`. Pay currency when it returns true, and move `kills++` there. `Spec` needs a new `damage` field. |
| Fire rate | `pull()`: `next[k] += 20/rps`. `fire()`: `lastInterval`. |
| Mag size | `reload()` (full check), `reloadTick` (need), `shellTick` (`< mag`), `refill*`, `givePrimary`, Hud low-ammo color |
| Reload speed | `reloadUntil = now + reload`. Scale the `Cue.at` checks (`el*reloadMul`, or pre-scaled lists). `SHELL_START`, `SHELL_PUMP` and the per-shell `reload` in `shellTick`. Keep the MAG_OUT/MAG_IN order so the model swap stays in sync. |
| Spread | the `fire()` spread formula, and bloom/bloomMax |
| Pierce and range | `trace`: `pierce` and `left` |
| Pellets | the `fire()` loop. Keep the 3-pellet cap for effects and sounds. |
| Recoil | the `recoilShot` up and side values |

### Random guns
The pack has only 5 models (`pistol`, `smg`, `rifle`, `shotgun`, `sniper` plus `_nomag`). Roll stat variants on top of a base Kind's Spec, which is a record and cheap to copy. Visuals and sounds follow `key`, so variants share them unless you add new model and sound keys to `build_pack.py GUNS` and `build_more.py`.

### Grenades
Physics, fuse, sounds and shake can be reused unchanged:
- Constants: `RADIUS 6`, `SPEED 1.2`, `LIFT 0.18`, `GRAVITY 0.06`, `DRAG 0.99`, bounce `v -= n*vn*1.35; v *= 0.62`, `FUSE 40`, `MAX 2`.
- Shake: 16 blocks, via `Guns.kick`.
- Near or far explosion sound, with the switch at 48 blocks.

Change `explode()`: iterate `targets.inRadius(at, RADIUS+1)` and keep the line-of-sight test (rays from `at+0.4` to sample heights 0.3, 0.9, 1.6 using `rayTraceBlocks`). Replace instant kill with damage falloff. `throwFrom` reads `g.guns.arms(p).grenades`.
